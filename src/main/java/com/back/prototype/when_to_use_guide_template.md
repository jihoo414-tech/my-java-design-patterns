핵심 사용 시나리오 (Core Use Cases)
- 객체를 새로 생성하는 비용이 크고, 기존 객체를 복제하는 비용이 더 저렴할 때
- 비슷한 상태를 가진 객체를 여러 개 생성해야 할 때
- 객체의 생성 과정이 복잡하거나, 많은 초기화 값과 설정이 필요할 때
- 런타임에 어떤 구체 객체를 생성할지 결정되고, 미리 준비된 원형 객체를 기반으로 새로운 객체를 만들고 싶을 때
- 객체가 가질 수 있는 대표적인 상태 조합이 제한적이고, 해당 상태를 미리 Prototype으로 준비할 수 있을 때
- 복잡한 Factory 계층이나 다수의 생성 로직을 줄이고, 객체 자체가 복제 책임을 갖도록 만들고 싶을 때
  자바에서 프로토타입 패턴(Prototype Pattern)의 실세계 적용 사례
  자바에서는 Object#clone()과 Cloneable 인터페이스를 이용해 기존 객체를 복제할 수 있습니다. 다만 실제 애플리케이션에서는 clone()뿐만 아니라 복사 생성자(Copy Constructor)나 copy() 메서드를 직접 정의하여 Prototype 패턴을 구현하기도 합니다.
  게임 개발에서는 동일한 기본 능력치와 설정을 가진 몬스터, 캐릭터, 아이템을 반복해서 생성할 때 기존 객체를 Prototype으로 두고 일부 속성만 변경하는 방식으로 활용할 수 있습니다. 문서 편집기나 그래픽 애플리케이션에서도 기존 도형, 문서, UI 컴포넌트를 복제한 뒤 필요한 속성만 수정하는 기능에 적합합니다.
  또한 복잡하게 초기화된 설정 객체나 템플릿 객체를 미리 만들어두고, 새로운 객체가 필요할 때 이를 복제하는 방식으로 사용할 수 있습니다.
  프로토타입 패턴의 장점과 트레이드오프(단점)
- 장점: 기존 객체를 복제하여 새로운 객체를 만들기 때문에 복잡한 생성 과정을 반복하지 않아도 됩니다. 유사한 객체를 여러 개 생성하는 코드를 단순화할 수 있으며, 객체를 생성하는 클라이언트가 구체 클래스의 생성 과정에 강하게 의존하지 않아도 됩니다. 객체 생성 비용이 큰 경우 성능상 이점을 얻을 수도 있습니다.
- 트레이드오프: 객체 내부에 다른 가변 객체가 존재하면 얕은 복사(Shallow Copy)와 깊은 복사(Deep Copy)를 구분해서 구현해야 합니다. 깊은 복사가 필요한 객체 구조가 복잡하거나 순환 참조가 존재하면 복제 로직 자체가 상당히 복잡해질 수 있습니다. 또한 단순한 객체까지 무분별하게 Prototype으로 구현하면 일반적인 생성자 사용보다 오히려 코드가 복잡해질 수 있습니다.
