
##  핵심 사용 시나리오 (Core Use Cases)
- 많은 수의 객체를 사용할때
- 객체 수가 많아 저장비용이 높은 경우 공유하는 내부데이터를 정의하고, 외부 상태를 별도로 관리
- 외부상태가 제거되면, 적은 수의 내부상태(공유)로 대체될 수 있다.
- 경량객체는 공유될 수 있으므로, 서로 다른 객체에 대해서도 식별할때 참을 반환할 수 있다.

---

**자바에서 플라이웨이트 패턴(Flyweight Pattern)의 실세계 적용 사례**

java.lang.Integer#valueOf(int)와 마찬가지로 Byte, Character 등 기타 기본형의 래퍼(Wrapper) 클래스가 이에 해당합니다. 자바의 String 클래스 역시 문자열 리터럴을 효율적으로 관리하기 위해 플라이웨이트 패턴을 활용합니다. GUI 애플리케이션에서는 메모리를 절약하고 성능을 향상하기 위해 폰트나 그래픽 컴포넌트 같은 객체를 공유하는 목적으로 플라이웨이트 패턴을 자주 사용합니다. 

**플라이웨이트 패턴의 장점과 트레이드오프(단점)** 

* **장점:** 객체의 인스턴스 개수를 줄여 메모리를 절약합니다. 상태 관리를 중앙화하여 상태가 불일치해지는 위험을 줄입니다.
* **트레이드오프:** 공유 객체를 관리하는 레이어가 추가되면서 복잡성이 증가합니다. 제대로 구현하지 않으면 공유 객체에 접근할 때 잠재적인 오버헤드가 발생할 수 있습니다.
